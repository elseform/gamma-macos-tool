# TODO: Оптимизация работы DirectX модулей и Wine/Proton в S.T.A.L.K.E.R. (xray-monolith / GAMMA)

## Контекст
В движке `xray-monolith` используются графические рендереры DirectX 9, 10 и 11. Несмотря на то, что основной рендер в Anomaly / G.A.M.M.A. — это **DirectX 11 (R4)**, под капотом движка сохраняется историческая зависимость от устаревшего заголовочно-библиотечного комплекса **Microsoft D3DX** (`d3dx9`, `d3dx10`, `d3dx11`, `DxErr`).

Microsoft вырезала библиотеки D3DX из современного Windows SDK начиная с Windows 8 / Visual Studio 2012. При запуске игры под **Wine / Proton (Linux / macOS / Steam Deck)** отсутствие нужных DLL или некорректное поведение встроенных реализаций Wine может приводить к сбоям.

Ниже приведен список задач и решений для упрощения работы Wine со стороны движка и инструментов установки (GAMMA Setup Tool).

---

## 1. Автоматическая поставка DLL-модулей DirectX рядом с `.exe` (Быстрое решение)
Wine и Windows всегда в первую очередь ищут DLL в папке исполняемого файла (`bin/`).

- [ ] Добавить в `gamma-setup-tool` автоматическую проверку и копирование необходимых нативных DLL DirectX в папку `bin/` приложения (рядом с `AnomalyDX11.exe` / `xray-monolith.exe`):
  - `d3dx9_43.dll`
  - `d3dx10_43.dll`
  - `d3dx11_43.dll`
  - `d3dcompiler_47.dll`
  - `d3dcompiler_43.dll`
  - `xinput1_3.dll`
- [ ] Убедиться, что пользователю Wine/Proton больше не требуется вручную выполнять `winetricks d3dx9 d3dx11 d3dcompiler_47` или настраивать `WINEDLLOVERRIDES`.

---

## 2. Замена D3DX на Header-Only и статические библиотеки в движке (Долгосрочное решение)
Избавление от динамической зависимости `d3dx11_43.dll` и `d3dx9_43.dll` на уровне исходного кода `xray-monolith`.

- [ ] **Математический модуль**:
  - Заменить устаревшие типы и функции `D3DXMATRIX`, `D3DXVec3...` на стандартный header-only **`DirectXMath`** (входит в стандартный C++ / VS toolset).
- [ ] **Текстурный модуль**:
  - В `dx10Texture.cpp` заменить функции загрузки/сохранения текстур (`D3DX11CreateTextureFromMemory`, `D3DX11SaveTextureToFile`) на статически линкуемую библиотеку **`DirectXTex`** или **`stb_image`**.
- [ ] **Геометрия и сетки**:
  - Заменить вызовы обработки геометрии D3DX на **`DirectXMesh`**.
- **Результат**: Исчезнет необходимость в `d3dx9_43.dll` / `d3dx11_43.dll`. Число системных зависимостей сводится к стандарту (`kernel32.dll`, `user32.dll`, `d3d11.dll`, `dxgi.dll`), с которыми Wine и DXVK работают из коробки.

---

## 3. Стандартизация компилятора шейдеров HLSL
- [ ] Перевести все вызовы компиляции шейдеров `D3DCompile` на системный **`d3dcompiler_47.dll`** (вместо устаревшего `d3dcompiler_43.dll` или вызовов из `d3dx9_43.dll`).
- **Результат**: `d3dcompiler_47.dll` входит в состав всех современных сборок Windows, Wine и Proton.

---

## 4. Оптимизация под DXVK (Direct3D -> Vulkan)
Под Linux / Steam Deck трансляция DirectX 11 в Vulkan осуществляется через DXVK.

- [ ] Использовать стандартные интерфейсы `IDXGIFactory1` / `IDXGIFactory2` без вызова закрытых/специфичных функций Windows API.
- [ ] Поддерживать флаг `--dxgi-old` для совместимости со старыми адаптерами и версиями DXVK.
